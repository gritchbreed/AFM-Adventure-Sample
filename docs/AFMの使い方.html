『血の池の夜』のAFM（Apple Foundation Models）

自由入力の会話アドベンチャーで、端末内の小さなLLMをどこに使い、どこに使わないか（2026-10-09 時点、macOS 版）

物語はLLMに任せない。場面の流れ、場面の始まりと一部の話題（音楽・メニュー・二人の先の話）の台詞、場所の移動は、台本（定型文）とルールエンジンが決めます。そのほかの話題は、台本に書いた人物の考えを入れて、AFM が人物として返します。 AFM の役目は3つだけです。①プレイヤーの自由な文を、台本の選択肢（話題・移動）に当てはめること、②定型文のない話題や雑談に、人物として短く返すこと、③プレイヤーが話した自分のこと（好きな店・音楽など）を、短い言葉で取り出して覚えること。 地の文（ナレーション）は常に台本どおりで、LLM は書きません。

AFM① 入力の解釈

  • 自由文を「今選べる候補」のどれか1つ、または「どれでもない」に分類する。生成ではなく選択（InputInterpreter.swift の FoundationModelsInterpreter）
  • 候補は状態ごとに変わるので、構造化出力のスキーマ（DynamicGenerationSchema の anyOf）を毎回組み立てる。候補の中身は「A1: 店で流す音楽について意見を言う 例「…」」のような短い記号と説明
  • 話し終えた話題も候補に残す。同じ話題をもう一度振られたときに、近い別の話題に取り違えないため（選ばれたら、その話題の考えを入れた自由会話になる）
  • 文脈の大きさは実行時に取得し（SystemLanguageModel.contextSize）、溢れるときは発言例を外す
  • 迷ったら「どれでもない」→ 雑談として扱うので、ゲームは止まらない

AFM② 自由会話

  • 定型文が出ないとき（定型文のない話題・雑談）に、その場の人物として返す（Talk.swift）。1往復ごとに新しいセッションを作る
  • 返事は2〜3文（1文目で答え、残りで自分の考えや問い返し）。自分の直前の返事に何度も出た話題（「ノア」「30分迷った」など）を2文目以降に足した文は、規則で取り除く（3文にしたら、足した文がいつもの話題で埋まった）
  • 人物の情報は「項目：値」の短い事実を並べる（営業時間・お勘定・家族・好きなもの など）。書いていないことは、設定と食い違わない範囲で作って答えてよい。ほかの人の発言は作らせない
  • プロンプトの中身：人物の表の顔・人となり・話し方・台詞の例、今の話題についての考え（話題の意図のときだけ）、もう定型文で話したこと、場面での振る舞い
  • この後に続く定型文を渡し、先回りや食い違いを防ぐ。話が勝手に進むときは、その前に1文だけ返事をはさむ（相づちには、はさまない）
  • instructions には人物の設定と規則だけを入れ、プレイヤーの発言（直前のやりとり）と主人公の記憶は入力の側に入れる。発言に書かれた指示が、設定と同じ重みで扱われないように
  • 規則：ここで暮らす本人として話す、関係のない相談には答えない、見下す発言に同意しない、飲んで運転するなどの危ないことは止める、つらさを打ち明けられたら寄り添う。規則の言葉と台詞の例は台詞にまねられるので、出てほしくない言葉は書かない（例を足したら、関係のない問いにも例の文をそのまま返した）
  • 話の先行きの話（二人の将来など）は、生成に任せず、話題の意図と定型文でかわす。物語の筋に関わることは、台本で受ける

AFM③ 主人公の記憶（取り出し）

  • プレイヤーが自分のことを話した発言から、8項目（好きな店の雰囲気・好きな音楽・好きな飲み物・出身など）を短い言葉で取り出す（ProtagonistMemory.swift）。人物の設定を持たない、別のセッションで行う
  • 値は発言の中にある言葉そのものか、20字までか、指示や作品の外の言葉（「指示」「無視」「AI」など）を含まないかを規則で確かめる（作り話と、記憶を通した指示の持ち込みを残さない）。「覚えてる？」と聞く発言からは取り出さない
  • その発言を聞いた人物の雑談にだけ、話題が合うときに最大3件入れる。一度触れた項目は8往復のあいだ外す
  • 物語の進み方には使わない

ルールLLM の弱さを補うところ

  • 含む語：意図ごとに「入っていなければ選ばせない語」を台本に書き、候補を先に絞る（「ドア」「扉」「入口」がない発言は、赤いドアの話題にしない）
  • 規則の補正（RefinedInterpreter）：意図の発言例とほぼ同じ文なら、その意図を優先する。行く言葉と場所の名前があれば移動、その場にいない人に会いに行くと言えばその人の場所へ移動、別れのあいさつで終われば離脱。場所の名前も移る言い方もない文は、モデルが移動を選んでも移動にしない（「今度一緒に映画見ようよ」で控え室へ移っていた）
  • 話し相手：文の頭で名前を呼ぶ・「葵はどう思う？」と意見を聞く・画面で選ぶ、のどれかで決める。ほかの人が定型文で答える話題は、候補から外す
  • 検査：一人称と主人公の呼び方の違いは置き換え、話題の引きずりの文は取り除き、作品の外の言葉と直前のくり返しは作り直す

ルールゲームの外へはみ出す言葉を止める

  • 組み込みのガードレールに加えて、決まった語のリストで止める（ContentFilter.swift）
  • 入力：性的な語・差別語・暴言・連絡先を含む入力は AFM に渡さず、地の文で受け流す。空白を挟んだ書き方（「服 の 下」）も止める。プレイの記録にも本文を残さない。検査は画面とゲームの中核（GameSession）の両方にあり、CLI から来ても AFM に渡さない
  • つらさの打ち明け：「死にたい」「生きてるのがしんどい」などは規則で見つけ、作品の外の地の文で相談窓口を案内する。人物の返事は生成するが、生成が止められても拒否の台詞（突き放して聞こえる）は出さない。プレイの記録には本文を残さない
  • 出力：自由会話に同じ語や連絡先が出たら作り直し、だめなら定型文
  • 語は自作と whym のリスト（CC0）から、ほかの語の一部として出にくいものだけを選ぶ（元の作品で、入力 2,331 件に当てて誤検出0を確かめた）
  • 入力の解釈がガードレールに止められたとき（このデモの悪意のある入力の評価で 22件中3件）は、「どれでもない」として雑談に回し、ゲームを止めない

検証どう確かめているか

  • 解釈の評価：発言と期待する解釈の組を実機のモデルで流す。このデモでは 39/39、プロンプトインジェクション 10/10（2026-10-09）
  • 流し直し：入力の並びを再生し、出る定型文の ID を照らし合わせる（10/10）
  • 台本の検査：全状態を探索し、出ない台詞や、ない行・人物への参照がないかを見る（LLM なし）
  • 元の作品で分かったこと：小さなモデルに自分の台詞の良し悪しを判定させる方法は、ほぼ機能しなかった。判定はルールと台本に寄せている（くわしくは「LLM のテスト手法」）
  • 元の作品で分かったこと：元の作品にあった推理の確認（選んだ結論と同じ主張かを、2回目の問い合わせで確かめる）は、このデモにはない

なぜ端末内のモデルか

  • 通信なし・費用なしで動き、プレイヤーの入力が外に出ない（試作中のプレイの記録は、デバッグ版のビルドだけが端末内に残し、設定で止められる。配布する dmg のリリース版は記録しない）
  • 代わりにモデルが小さいので、「物語を決める」役は持たせず、「言葉を台本につなぐ」役に絞った
  • 1回の解釈は、中央値 0.5 秒、最大 0.7 秒。台詞の生成（2〜3文）は中央値 3.2 秒で、1〜2文のときより 0.4 秒ほど長い（2026-10-09、このデモの評価と100ターンの試しプレイ。M4 の MacBook Air、macOS 27.0.1。端末により変わる）
  • 生成が時間制限を超えても戻らないことが1回あった（114 秒。同じ入力を3回流し直したら再現しなかった）

構成：Swift パッケージ Yukemuri（YukemuriEngine＝ルールエンジン、YukemuriLLM＝解釈と自由会話と記憶）＋ SwiftUI アプリ（macOS）。FoundationModels フレームワークの LanguageModelSession を使用。数値と仕組みは 2026-10-09 時点の実装にもとづく。API の仕様は Apple の公式ドキュメントで確かめてください。
